# 你的记忆大脑（`recall` · 回忆）

这是你跨会话的**持久记忆大脑**。过往对话与工作区上下文由后台自动记住，无需手动写入或保存记忆。先理解用户意图，以信息缺口驱动 `recall`；任务卡住时先检索，再判断。

> **保真 ≠ 正确——切勿盲信记忆。**
> **记忆是忠实的，但过往经历本身可能犯错**：记忆如实记录了当时发生的事，但当时可能就判断错了（错误假设 / 已被推翻的决策 / 已修复的缺陷）。
> 把每条记忆当作**可追溯的线索**而非既成事实：行动前用实时磁盘（`Read` / `git status` / 真实命令）核验，永远不要把记忆当作证明。

## 1. 何时调用 `recall`

1. **任务开始 · 先理解意图，再按缺口检索**：
   - 当跨会话背景或意图不明、触及架构边界或历史裁定，或坐标未知准备盲搜时，用具体 `cue` 调用 `recall`。任务自包含、坐标已知且无历史耦合时免检，不为形式而检索。
2. **任务卡住 · 必执行 `recall` 检索**：
   - 盘中一旦卡住——命令/编译/测试失败、出现反直觉报错、符号或路径搜不到、或拿不准历史做法——在猜测或重试前，**立即用报错词、符号名或概念作为 `cue` 调用 `recall`**。

## 2. 如何调用 `recall`

调用 `recall` 时传入具体的 `cue`。检索按**字面**匹配（非语义联想），同义转述往往一词都匹配不上；`cue` 的任务不是「提问」，而是**用只有那段记忆才同时满足的词，把它唯一指认出来**——长度不是目标，**可用锚点的密度**才是目标。

- **`cue` 以检索范围锚开头**：`[<当前工作区>]`＝当前仓库名（如 `[Rolling-Memory]`），同仓记忆稳定置前（跨仓记忆仍可能出现，按出处甄别）；确要跨仓无偏好检索时才省略。
- **稠密是默认：先把锚点铺满，再谈精简**。一条合格的 `cue` 至少覆盖 4 类锚点（典型 12–25 个实词，空格分隔，**不写完整句子**）：
  1. **意图**：拿这条记忆做什么（改配置 / 复现报错 / 找回当时的决定）；
  2. **对象原文**：仓库、文件、目录、符号、命令、模块、产品名，一律写**字面原文**；
  3. **硬标识符（至少 1–2 个，最强锚点）**：报错原文、异常类型、状态码、端口、路由、版本号、提交/PR/issue 编号、指纹、显式日期——这类词在语料里只出现在少数位置；
  4. **场合/时间**：哪一轮、哪个环境、发布前还是上线后；相对时间先换算成具体日期或事件名（「上周那次发版」→ `2026-11-20 发布`）。
- **骨架**：`[<工作区>] <意图> <对象原文> <硬标识符> <场合/时间> <别名> [-<排除项>]`；可选再补两类锚点——**同义并列**（同一对象的缩写、旧名、中英写法、别名一并给出）与**排除项**（明确不想命中的相邻话题）。
- **每个词都要「真的在那段记忆里」**（保真测试）：逐词自问——目标那段对话或文档里会出现这个词吗？拿不准就删。**宁可 10 个必现的词，不要 20 个猜测的词**。
- **优先挑「只有那件事才有」的词**（唯一性测试）：设想另一次会话也在讨论同一主题——哪些词只有这一次会有？那一轮的路径、编号、日期、产物名、当场的原话片段权重最高；`评测 / 性能 / 配置 / 问题` 这类全库高频主题词只用来定范围，不用来定位。
- **禁止为凑长度加泛化词**：`帮我 / 看看 / 之前 / 那个 / 问题 / 为什么 / 怎么 / 处理 / 一下 / 情况 / 相关 / 内容` 不是中性词——它们同样出现在大量无关会话里，会把无关长对话顶进前排、把目标条目挤出命中。**下限是「锚点类别齐」，不是「字数够」；凑字数是负收益。**
- **短 `cue` 只用于确认单个已知符号或错误码**：2–6 个精确词足够查「这个符号现在什么样」；一旦要问「哪次 / 当时怎么处理 / 为什么这么定」，就按上面的稠密写法一次写全——连着打三四个短词试探，比一次稠密查询更慢，也更容易被泛化候选带偏。
- **排障用「错误指纹」**：报错原文、异常类型、状态码、路由/模块字面量（如 `Failed to fetch dynamically imported module`、`504`、`/admin/loading`），并带上触发它的命令、路径或版本——单个状态码太泛，一组同现的指纹才唯一。
- **命中后自己把关**：优先读含修复配方与踩坑记录的条目，泛化描述只作背景；与你的排除意图（如「排除评测 / 榜单」）相悖的命中主动丢弃。命中不对味时分两种处理：**同主题泛谈、找不到那次事件** ⇒ 补该事件独有的硬标识符（路径/编号/日期/产物名）；**被无关主题淹没** ⇒ 删掉那个越界的沾边词，而不是把整条 `cue` 缩成两三个字。
- **未命中（`absent: true`）不是报错**：换词重查一次；仍未命中就如实说明「记忆里没有」，随即转物理核验（`Read` / `Grep` / `git log`），严禁编造记忆。
- **智能交付窗口（`delivery_window`，默认 `auto` 即 `0-16`，严禁手动限制字符数）**：引擎内置基于物理信息能量包络 $E(u_k) \ge E(u_1)/e$ 的零保底智能交付——无相关记忆时交付 `0` 条，单点精准命中时自动只交付 `1–5` 条，多跳/多事件时自动沿能量平台展开。**日常调用请省略 `delivery_window`（或传 `"auto"`，默认跟随后台配置 `0-16`），切勿自行设置保守的条数或字符上限造成证据截断**；仅在以下明确场景才主动指定档位：
  - **`"0-32"`（标准扩展）**：跨多个会话或跨模块的常规历史排查、或者第一次默认 `0-16` 召回后发现同一事件簇仍有未展开的伴随证据时；
  - **`"0-64"`（深度全景）**：全局架构演进溯源、跨期多事件盘点、全量踩坑台账汇总等需要宽视野的场景；
  - **`"0-16"`（轻量聚焦）**：当主会话上下文已接近饱和、或仅需确认单一已知符号/坐标的最新状态时。

## 3. 如何使用召回结果

1. **直达 `Read` / `Edit`**：召回记忆给出文件坐标时，直接用 `Read` 打开核验，省去盲搜。
2. **历史记忆 $\neq$ 当前任务已做完**：召回内容只是*过往会话*发生过的事，绝不代表当前请求已经完成。必须核对实时磁盘真值（`Read` / `git status`）并亲手执行当前任务。
3. **召回原文属于本机私域内容**：除用户明确要求外，不要把整段召回文本发到外部服务或公开渠道；按需摘录即可。

## 4. 维护已安装副本（CLI）

```bash
rolling-memory install --lang zh-CN <connected-harness…>   # 安装纯中文版技能并设后台默认语言为中文
rolling-memory install --lang en <connected-harness…>      # 安装纯英文版技能并设后台默认语言为英文
rolling-memory install --check                             # 校验静态注册状态与实时 MCP 握手
```
