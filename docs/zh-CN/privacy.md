# 隐私与本地数据说明

**[简体中文](privacy.md) · [English](../privacy.md) · [返回文档中心](README.md) · [返回仓库主页](../../README.md)**

Rolling Memory 的隐私承诺只有一句话：**你的全部原始明文、沉淀记忆与本机主密钥 100% 保存在你自己电脑的本地 SQLite 保险箱内——记忆引擎不发起任何外部网络请求。**

这不是一纸承诺：它由架构强制执行（记忆组件自身根本不存在出网通道），并由公开测试套件中的零泄漏自动化检查持续守卫。请注意，若你的编程助手使用了远端模型 API，召回内容将作为上下文的一部分发送给模型服务商。下文说明哪些数据留存在本地、你的记忆资产在本地为何足够安全，以及你如何亲自验证。

---

## 1. 哪些数据永远不会离开本地金库

| 资产 | 存放位置 | 记忆组件出网 |
|---|---|---|
| 原始对话、挂载文档与召回结果 | 本地 SQLite 金库（默认 `~/.local/share/rolling-memory/memory.db`） | **0 —— Rolling Memory 不外发** |
| 沉淀的 L3 `Noetic` 印迹（$Q$ + `cited_unit_ids[]` + $A$） | 同一本地金库 | **0** |
| 本机主密钥 / 金库元数据 | 同一本地金库（目录 `0700`、文件 `0600`） | **0** |
| 召回索引（SQLite FTS5 `trigram` + BM25） | 同一本地金库 | **0** |

- **本地模式是默认模式，也是本发布版唯一的模式**：不需要云端账号、没有注册流程、没有后台上传、没有统计埋点、没有崩溃上报、没有遥测；
- **历史受众限制**：不要依赖 `private` 标签或 `reader=deliverable` 保护所有来源的敏感内容。分享召回结果或将其发送给模型前，请先检查内容。

## 2. 你的记忆资产在本地为何足够安全（纵深防御）

工程记忆（架构决策、代码坐标、排障复盘与个人知识库）是高价值资产。Rolling Memory 以多层本地防御存放它们：

### 2.1 本机物理主权：单文件 SQLite 金库 + 操作系统 `0700/0600` 权限锁死

- **100% 本地落盘**：全部原始对话、文档切片、沉淀问答与本机主密钥都保存在本机单个 SQLite 文件里（默认 `~/.local/share/rolling-memory/memory.db`）；
- **严格的操作系统文件权限**：数据目录以 `0700` 创建（仅当前操作系统属主可访问），数据库与密钥文件以 `0600` 创建（仅你可读写，同组与其他用户一律拒绝）；
- **无缝继承全盘与便携卷加密**：全部状态集中在一个零依赖 `.db` 文件里，天然受 macOS FileVault / Linux LUKS / Windows BitLocker 全盘加密保护，也可以直接放进硬件加密 U 盘（`rmem init --portable`）或经 `ROLLING_MEMORY_DB` 落到加密磁盘镜像上。

### 2.2 L1 `Background` 原位按需流式读取：零全文冗余拷贝

挂载本地知识库或代码库到 L1 `Background` 时：

- **你的代码库不会被复制进任何外部数据库**：Rolling Memory 采用**原位按需流式读取**架构——本地 SQLite 只保存轻量分块元数据（文件路径、`mtime_ns`、字节偏移），而不是把海量原始文档复制一份；
- **最小化本地暴露面**：你的原始 `.md`、`.pdf`、`.docx` 与源码文件始终留在自己的工作目录；当文件被编辑或删除时，增量核对会自动失效依赖它的本地 `Noetic` 印迹。

### 2.3 历史受众标签

历史记录可能带有受众标签，但限制可能无法覆盖所有来源。不要将这些标签或 `reader` 设置作为访问控制边界。请勿将凭据和其他敏感内容放入共享上下文；分享召回结果或将其发送给模型前，请先检查内容。

### 2.4 内置本地 FTS5 召回与 100% 零厂商锁定

1. **离线优先召回（`Client SDK Default Recall`）**：
   - 本地金库在引用链之外维护原生 SQLite FTS5 词法–时序索引；哪怕断网、在飞机上或所有网卡都关闭，你的本地记忆资产依然 100% 可检索、可阅读；
2. **100% 开放格式与 BYO-Storage 自由**：
   - 本地金库使用 SQLite。部分记忆引用数据库之外的会话文件和挂载文件；仅保留金库不能保留这些原件。

### 2.5 密钥与日志卫生

- **API 密钥永不写盘入库**：密钥只从环境变量或 `0600` 权限文件读取（POSIX 上对同组/其他用户可读的文件一律拒绝），绝不写入 SQLite、`config.toml` 或日志；
- **日志零消息体与自动脱敏**：生命周期日志（`~/.local/state/rolling-memory/rolling-memory.log`，2 MB 轮转）只记录事件名、计数、时延与脱敏后的错误摘要——从不记录对话正文，并自动脱敏 API Key、Bearer、Access Token 等模式。

## 3. 亲自验证它

```bash
rolling-memory doctor --json                    # 查看模式、出网策略、密钥权限与数据库健康
rolling-memory check --json                     # 查看可用的数据库完整性检查
go test ./...                                   # 公开测试套件：零明文/零向量出网检查
```

- Go 测试套件包含本地模式网络行为检查，但不能证明所有来源均执行受众限制；
- 网络层同样可审计：在本地模式进程工作期间开启任意抓包或防火墙（`tcpdump`、Little Snitch 等）观察——不会出现任何与对话相关的对外请求。

## 4. 已知边界与威胁模型

- **物理设备与本地 root 威胁模型**：本地 SQLite 金库在本地磁盘上以明文（`0600` 权限）存放，以换取亚毫秒级读取与透明的用户审计。如果物理设备丢失或共享主机被攻破属于你的威胁模型，请启用操作系统全盘加密（FileVault / LUKS / BitLocker），或把 `memory.db` 放到加密卷上；
- **本地访问**：同一操作系统用户账号下的其他进程可能读取 `memory.db` 及其副本。

---

## 5. 数据主权：导出、删除、备份、迁移

- **零采集**：本地模式发起 0 次外部网络请求，不包含任何统计、崩溃上传或使用上报；
- **导出**：JSON 导出不可用，因为它不包含金库和引用原件。已有 JSON 导出仍可导入兼容数据库，但不是完整备份；
- **备份**：SQLite 的 `.backup` 可生成一致的数据库副本，但不是自包含备份。须另行保留所引用的会话数据库或文件以及挂载源文件，包括其路径。所有副本可能包含隐私数据和密钥，须妥善保护；`rolling-memory doctor --json` 可查看金库路径；
- **删除**：停止进程后删除 `memory.db` 及其 `-wal` / `-shm` 边车文件即可移除本地金库；挂载的后台源文件不会被删除；
- **迁移**：仅复制金库不会迁移引用原件。须保留其原路径并另行验证访问；`rolling-memory doctor` 不能证明所有引用均可读取。

## 6. 云端能力预览（申请制）

Rolling Memory 的云端记忆引擎（Rolling Autonoetic Memory Engine · 洛灵自知记忆引擎）是一项独立能力，将以**申请制**逐步开放；在线注册已关闭。请邮件 [pick@psychologylake.org.cn](mailto:pick@psychologylake.org.cn) 申请（支持：[support@psychologylake.org.cn](mailto:support@psychologylake.org.cn)）。它不属于本次发布：本发布版为纯本地模式，接入说明仅提供给获批申请人。

由于你的全部原始数据始终留在本地金库，任何阶段都**不存在厂商数据绑架**。未来当团队具备足够的生存与发展保障时，我们仍完全不排除将云端核心引擎彻底开源——完整立场见 [DECLARATION.md](DECLARATION.md)。
