# MCP Single-Tool Contract (`recall` · 回忆)

**[English](mcp.md) · [简体中文](zh-CN/mcp.md)**

Rolling Memory's MCP server is a newline-delimited JSON-RPC 2.0 process over stdio (`rolling-memory mcp`) exposing **a single tool to the host Coding Agent: `recall` (`回忆`)**.

Under the **Rolling Autonoetic Memory Engine memory model**, the agent **never needs to call a manual memory-writing tool**:
- **L1 `Background`**: Mounted local workspace directories are chunked in-place; the initial mount indexes in full, then file-level mtime/size and per-chunk SHA-256 deltas keep unchanged chunks out of the work queue (plaintext stays on local disk, indexed locally). Mounting is idempotent per physical file — the same folder imported twice, or a parent folder together with one of its subfolders, never indexes anything twice (a file belongs to its deepest mount). Removing a mount only clears the entries of files no other mount covers; files still covered by another mounted folder keep their index and traces.
- **L2 `Episodic`**: Every conversation turn is captured losslessly by the background watcher after a quiet window (the `rolling-memory mcp` process runs the watcher; run `rolling-memory sync reconcile` to reconcile immediately) — **raw plaintext is locked 100% in the local SQLite vault** and indexed locally.
- **L3 `Noetic`**: Every `recall` query that hits real evidence units automatically crystallizes a local `Noetic` trace linking the query and `cited_unit_ids[]` (**Recall IS Memory / Retrieval-Induced Consolidation**).

## 1. Server Startup & Environment

```bash
rolling-memory mcp        # Built binary or launcher shim generated by `rolling-memory install`
```

| Environment Variable | Default | Purpose |
|---|---|---|
| `ROLLING_MEMORY_CONFIG` | `~/.config/rolling-memory/config.toml` | Configuration file path |
| `ROLLING_MEMORY_DB` | `~/.local/share/rolling-memory/memory.db` | Local SQLite plaintext vault path |
| `ROLLING_MEMORY_SCOPE` | `default` | Active memory scope |
| `ROLLING_MEMORY_MODE` | `local` | Operating mode — `local` is the default and the mode shipped in this release |
| `ROLLING_MEMORY_PORTABLE` | Unset | Portable USB payload root directory (or `1` for auto-resolve) |
| `ROLLING_MEMORY_MCP_DEBUG` | Unset | Set to `1` to log error stack traces to `stderr` |
| `ROLLING_MEMORY_MCP_IDLE_EXIT` | `30m` | Idle self-retirement budget (Go duration); `0` or negative disables idle exit |

`initialize` response:

```json
{
  "protocolVersion": "2024-11-05",
  "capabilities": {"tools": {"listChanged": false}},
  "serverInfo": {"name": "rolling-memory", "version": "<repository VERSION>"},
  "instructions": "..."
}
```

The server opens SQLite lazily on the first `tools/call` so `initialize` and `tools/list` always succeed quickly.

**Process lifecycle (self-retirement watchdog)**: stdio is one process per connection, and host reconnects leave abandoned connections behind. The watchdog makes a session exit on its own in three cases: (1) the parent harness is gone (orphan); (2) the executable on disk no longer backs this process (stale generation); (3) input stayed silent past `ROLLING_MEMORY_MCP_IDLE_EXIT` (default `30m`, reset on every received input). stdio hosts respawn a fresh process on the next call, so retirement is cleanup, not failure; the exit reason reaches `stderr` only under `ROLLING_MEMORY_MCP_DEBUG=1`.

## 2. The Single Tool: `recall` (`回忆`)

### 2.1 Input Parameters

| Parameter | Type | Description |
|---|---|---|
| `cue` | string | Literal search clue (required for `mode=full`/`probe`): prefix with `[<workspace>]` (e.g. `[Rolling-Memory]`) to prioritize current-repository memories, followed by 2–6 exact tokens, file/symbol names, status codes, or error fingerprints (avoid natural-language paraphrasing; if noisy, drop broad words and retry with fewer exact tokens) |
| `scope` | string | Override default memory scope |
| `reader` | `owner` \| `deliverable` | Defaults to `deliverable`; historical audience restrictions may not be enforced across all sources. Review results before sharing. |
| `mode` | `full` \| `probe` \| `recent` | `full` returns `bands × chains`; `probe` returns a compact existence receipt (summaries truncated to 160 chars); `recent` lists the newest entries in pure time order (no semantic matching; `cue` is ignored) |
| `result_unit` | `band` \| `item` | Delivery unit: subject bands (`band`, default) or flat source items (`item`) |
| `rank` | bool | Item-mode grouping switch: `true` (default) groups by memory unit → source block; `false` delivers pure relevance order |
| `asof` | string \| int | Reserved; do not use (requests specifying this filter fail closed) |
| `window` | object | Reserved; do not use (requests specifying a boundary fail closed) |
| `caps` | object | `{bands, nodes, chars, chains, rows, raw}` delivery budget overrides. `raw` defaults to 10 and supports up to 64; `bands` supports up to 64. The default text budget is 16,000 characters unless configured otherwise. |
| `session` | string | Reserved; do not use (requests specifying this filter fail closed) |
| `offset` | int | Band pagination offset |
| `deep` | bool | Optional query-hint expansion; skipped automatically in zero-LLM local mode |

### 2.2 Full Receipt & Real-Time `Noetic` Crystallization

In full mode, the tool returns a budget-capped `<rolling-memory-recall ...>` block ready for context injection.

Key fields:
- `absent`: no matching memory found. **This is not an error** (`isError = false`); state "no record" and continue.
- `gaps`: diagnostic flags (`empty_graph`, `budget_exceeded`, etc.).
- **Time labels**: memory timestamps use local wall-clock time at second precision with an explicit UTC offset; the block header carries the current time (`now`), so a recalled moment can be placed against now without guessing the date or zone.
- `meta.legs`: per-leg hit counts; `meta.activation`: salience ledger (0 LLM calls).
- **Real-Time `Noetic` Crystallization**: when `mode != "probe"`, any `recall` that hits real evidence units (`cited_unit_ids` non-empty) persists the Q/A handle in the local citation index and grows an L3 `Noetic` node with `cites` edges in the local graph in real time (0 LLM calls).

### 2.3 Probe Receipt (`mode="probe"`)

```json
{
  "scope": "mem:self",
  "absent": false,
  "hits": [
    {"id": "ep_...", "summary": "...", "date": "2026-11-10", "status": "active",
     "anchor": "ep_...", "relative_strength": 1.0}
  ],
  "gaps": {},
  "meta": {"count": 20, "cue_coverage": 0.48, "elapsed_ms": 412, "engine": "Rolling Autonoetic Memory Engine", "noetic_hits": 1}
}
```

`relative_strength` compares an item's retrieval weight with the candidate peak in the **same source family**. Families use separate scales, and the peak candidate may not appear in the final results. This value is not a probability, relevance score, or measure of truth, and cannot be compared across searches or families.

When available, `meta.cue_coverage` measures the share of unique cue atoms found in the first candidate's source text. It is not an aggregate over all results or a measure of semantic relevance. A missing field does not necessarily mean zero overlap; longer source text may also increase overlap.

## 3. JSON-RPC Error Semantics & Lifecycle Hooks

| Condition | JSON-RPC Response | Notes |
|---|---|---|
| Unknown method | `error.code = -32601` | Standard JSON-RPC method not found |
| Unknown tool / invalid params | `error.code = -32602` | Invalid tool arguments (`recall` is the only exposed tool) |
| Malformed JSON line | `error.code = -32700` | Parse error; server continues reading next line |
| Database / config / egress failure | `result.isError = true` | Redacted error message in text content |
| Fact not held locally | `result.isError = false`, `absent = true` | First-class epistemic state, not an error |

Lifecycle hook (`UserPromptSubmit` → `hook recall --json`) is fail-open (always exits `0`):
- **Single Hook (`UserPromptSubmit` Only)**: Following the principle that *actions not requiring an LLM decision do not need a hook*, only `UserPromptSubmit` runs. It does **not** blindly inject search results; it emits a 1-line strong hint so the **LLM decides when and what to `recall`**, while the plugin core automatically harvests the previous completed turn into the local vault as content-addressed `layer="episodic"` (`ep_<sha256>`).
- **MCP `recall` (`L3 Noetic`)**: When the agent calls `recall`, relevant memories are retrieved and crystallized into `layer="noetic"` (`nt_*`) with `cited_unit_ids[]`.
- **Zero Egress**: queries, conversations, and memory all stay inside the local SQLite vault — this release is pure local mode and nothing leaves the machine.
