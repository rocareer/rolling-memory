## 1. 发布边界：本仓库发布什么、不发布什么

**Rolling Memory** 是面向 AI 编程助手的本地优先记忆工具，由 **Rolling Autonoetic Memory Engine（洛灵自知记忆引擎）** 驱动。本仓库发布**纯本地模式（`local_plain`）**，并包含整套可独立审计的客户端面：CLI 与多宿主插件、本地 SQLite 明文金库、四语言 SDK、传输层出口闸门，以及 `rmem eval` 评测运行器。

高阶**云端记忆引擎**、**脉冲密文模式（`pulse_cipher`）**以及**高阶关系簇与多模态重解析等研究核心**属于闭源专有技术，**不对外开放、不在本仓库中**，且本仓库发布的任何功能都不依赖它们——本发布版 100% 以纯本地明文模式（`local_plain`）完全离线运行，零外部网络请求。

作为密码学与可信 AI 研究者，我们拒绝任何虚伪的借口——**我们绝不宣称“靠隐藏算法代码来保护用户的数据安全”**。根据**柯克霍夫原则（Kerckhoffs's Principle）**，真正的隐私安全只依赖于可独立验证的信任边界与用户可见的数据路径，而不依赖于把代码藏起来。上述边界基于三条客观工程准则：

1. **最小可信计算基与可验证的本地数据路径**：
   - 任何用户最核心的两个问题是：**「我的数据到底存在哪？」**以及**「我能否亲自验证没有任何东西离开本机？」**
   - 本地客户端、SQLite 明文金库、标准 SDK 与传输层出口闸门都刻意保持极小，安全工程师可直接通读并独立确认：**本发布版本地模式下，原始文本与本机主密钥永远不出本地金库**。
   - 本地金库使用 `0700/0600` 权限隔离，金库和引用原件可受操作系统全盘加密（FileVault / LUKS / BitLocker）保护；L1 `Background` 采用原位按需流式读取（零全文冗余拷贝）；内置本地 FTS5 兜底检索与开放 SQLite / 可插拔本地存储格式，保证 100% 离线可用、零厂商锁定（详见 [`privacy.md`](privacy.md)）。
2. **端侧零算力负担**：
   - 高开销的全局共现网络、多粒度情景记忆分裂赋址、分形干句提纯（自动剥离重复日志死循环与模板水话）以及跨设备状态同步，属于云端面的职责；端侧因此保持**毫秒级响应与极小内存占用**，零后台大模型调用、零向量化 API 账单。
3. **对抗记忆投毒防御与零厂商锁定**：
   - 开放环境下的 Agent 面临**对抗性记忆投毒（Adversarial Memory Poisoning）**——恶意网页、第三方工具输出或污染语料会试图通过高频刷屏或关键词堆砌篡改记忆权重、劫持 Top-1 召回；
   - 你的明文留在你自己的本地 SQLite 文件中，随时可导出；端侧不依赖任何服务账号。

> **评测语料不随本仓库分发。** 我们发布读数所用的基准数据集由读者自行从上游基准项目获取，并以公布的 `SHA-256` 摘要钉住——详见 [`benchmarks.md`](benchmarks.md)。可复现性依赖这些 pin 与冻结的判分协议，**不依赖随包语料**。

## 2. 诚实披露与免责条款（Disclaimer）

2. **评测诚实与随时开放质疑/验证（自备语料 + 自配 LLM 自付成本）**：公开读数均携带语料密码学 pin（`SHA-256`）与判官提示词 pin（`SHA-1`）。语料本身**由读者自备**（取自上游基准项目）；严禁篡改评测语料、严禁针对错题手工补塞记忆单元或改图特调。**只要语料就位，任何人都可以随时用 `rmem eval` 复现检索路径**（纯检索层复算 0 成本断网可跑；若运行端到端问答与判官打分 `--answerer llm --judge llm`，需自行配置 LLM 接口并自付推理/Token 成本）。两种行为是刻意分开的：依赖语料的**测试在语料缺失时跳过（skip）**，因此本仓库自带测试在没有语料时保持全绿；而**`rmem eval` 本体在语料缺失时以明确、可操作的错误退出**，绝不凭空产出读数。
